# CylinderFlow stride-8 / prefix-65 contract

Contract version: `cylinderflow.stride8.prefix65.v1`. Evaluator version: `cylinderflow.physical_mesh.v1`.
This file, `cylinderflow/` and `tests_cylinderflow/` are identical in all three independent repositories.

Use [DingDong1921/mgn-cylinderflow-stride8-75frames](https://huggingface.co/datasets/DingDong1921/mgn-cylinderflow-stride8-75frames) at revision `8eae2c7a697e7d01f3b98f4d642ea476784df84a`.
The two input files are `cylinderflow_stride8_75frames.h5` and `cylinderflow_stride8_75frames_manifest.json`.
The HDF5 contains `trajectory_0000` through `trajectory_1099`, each with `mesh_pos [N,2]`, triangular `cells [C,3]`, `node_type [N]`, and physical `uvp [75,N,3]` in **u, v, p** order. Mesh size varies by trajectory. Labels are normal=0, inlet=4, outlet=5, wall=6. Train is 0..999 and Validation is 1000..1099. Test is unsupported.

Read stored frames **0..64 only**, equivalent to raw indices **0,8,...,512**, with physical interval **0.08 s**. There is no additional subsampling, temporal phase, or interpolation. Frame 0 is observed; frames 1..64 are predictions. Every saved prediction is `[65,N,3]` on the original mesh. The remaining 10 stored frames never enter targets, normalization, latent caches, checkpoint selection, or metrics.

`prepare` recomputes Train-only normalization over the permitted prefix. Published 75-frame statistics and the existing Text2PDE statistics have a different temporal support and are not used. AROMA and EAGLE use population moments pooled over nodes and the 65 unique Train frames. EAGLE's fourth internal channel is `q=0.5*(u*u+v*v)`; its channels are `[u,v,p,q]`. MGN uses equal-trajectory moments of current UV on frames 0..63, UV increments across the 64 pairs, next pressure on frames 1..64, and directed edge displacement/length. MGN increment variance includes variance from its 0.02 normal-node input noise. All denominators have an explicit small zero-variance floor.

Inference receives `initial [N,3]`, points, triangles/edges, node labels, and optional clusters. It has no future-reference argument. EAGLE receives a repeated initial state as storage for its native time axis; only its loss-target return uses the later entries. Its explicit boundary argument clamps inlet/wall **velocity** to first-frame values. Pressure, the internal q channel, and outlet are predicted freely; the padded ghost state stays zero. MGN also clamps inlet/wall velocity in recurrent state. AROMA advances latent state freely and writes these velocity boundaries only to decoded outputs; `pre_boundary` predictions are retained. Thus the boundary treatment's location differs between latent and physical recurrent models and is recorded explicitly.

## Training and selection

AROMA AE draws one of the 65 frames per trajectory per epoch. Frozen AE caches are posterior means `[65,32,8]` from Train only; dynamics traverses all 64 adjacent transitions for each native trajectory batch. Its four DDPM scheduler timesteps and v-prediction objective match the pinned upstream refiner. MGN trains all 64 pairs per trajectory. EAGLE draws a 6-frame window with inclusive start 0..59 per trajectory per epoch, preserving its differentiable rollout loss and capacity-constrained geometric clusters of size 10. Static preprocessing may read Validation mesh geometry but never uses Validation values to fit normalizers or latent caches.

During training, the monitoring subset consists of `round(linspace(0,99,24))` positions in the official Validation list, always beginning at frame 0. Select checkpoints lexicographically by `(failed clips, mean trajectory UV relative RMSE, optimizer update)`; earlier updates win exact ties. AROMA AE is selected by posterior-mean reconstruction on frames 0,21,43,64 of this subset, explicitly an AE diagnostic. AROMA dynamics uses sampling seed labels 0/1/2, with actual PRNG seed derived from `(training seed, trajectory index, seed label)` and recorded in every row; MGN/EAGLE use label 0. Sampling is never best-of-three.

`evaluate --mode select` ranks candidate checkpoints on these 24 trajectories. `--mode validation` accepts exactly one already-chosen forecasting checkpoint and evaluates all 100 Validation trajectories (300 AROMA clips, 100 MGN/EAGLE clips). Freeze the checkpoint and configuration before this full Validation pass; this command does not authorize Test access. Every failed clip remains in JSONL/CSV and failure counts. A trajectory with any failed sample has no finite trajectory mean; selection first minimizes failed clips and then averages the complete finite trajectories. The summary exposes both denominators. This prevents favorable surviving seeds from standing in for a failed trajectory.

## Metrics and saved arrays

All comparisons restore physical quantities and exclude the observed first frame from forecast aggregates. Node weights are one third of incident triangle areas. UV relative RMSE is `sqrt(sum(area*UV_error^2)/sum(area*GT_UV^2))`, summed over future times, nodes and the two velocity components. The 65 per-frame values and final-frame value are retained. Raw pressure RMSE is area weighted. Gauge-free pressure removes each frame's area-weighted pressure-error mean. Vorticity `dv/dx-du/dy` and divergence `du/dx+dv/dy` use piecewise linear triangle derivatives and triangle-area weights. Energy and enstrophy use domain-area means; spectra are temporal velocity spectra, not spatial turbulence spectra. Correlations and energy-series best lag in ±10 frames provide correlation/phase diagnostics; energy lag is a proxy, not a vortex-tracking measurement. Boundary subsets additionally use unweighted node/component RMSE, labeled separately from area-weighted domain errors.

Sampling metrics are averaged within each trajectory before equal-trajectory aggregation. Scalar summaries retain mean, median, p90, min, max and finite sample count. `case_metrics.jsonl`, `case_metrics.csv`, `frame_metrics.csv`, `trajectory_metrics.csv`, `summary.json` and `failures.json` accompany all predictions. Compressed NPZ files include physical prediction/target/pre-boundary arrays, mesh, labels, exact raw indices and physical times, allowing offline re-evaluation and rendering without weights.

Timings use synchronized wall time: `encode_seconds` is AROMA's external AE encoding (zero for MGN/EAGLE), `model_seconds` includes recurrent model calls and their native internal encoders/decoders, `decode_seconds` is external AE decoding or physical output conversion, `preprocess_seconds` is graph/tensor preparation, and input/output I/O are separate. CUDA stage timing is instrumented; these values are not isolated-kernel benchmarks. Media rendering is timed separately and excluded from model cost. Training logs record losses, learning rate, gradient norm, examples seen, updates, elapsed wall time, and CUDA peak memory. Actual examples use a frame for AE, a transition for dynamics/MGN, and a six-frame window for EAGLE.

Checkpoints contain model, optimizer, scheduler, scaler, Python/NumPy/PyTorch RNG state, epoch and within-epoch cursor, actual exposures, code identity, full configuration, normalization and AE/cache dependency identity. Source identity uses Git commits and the pinned dataset revision; this workflow does not calculate content hashes. Runtime directories are unique, and resume requires an explicit checkpoint and matching run/configuration. No data, new weights, run logs, or private context belongs in the code repository.

EAGLE also saves physical `eagle_state_uvpq [65,N,4]` and `eagle_pre_boundary_uvpq [65,N,4]` alongside the common three-channel arrays. The evolved fourth channel is retained as predicted, rather than recomputed from predicted velocity, so its recurrent role is independently traceable.
